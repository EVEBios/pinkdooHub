Authority: 用户已确认的门店库存规划、参考双列排布、项目 Ribbon Ledger；用户授权视觉先完成后调整。固定结构直接实现，不另开方案选择。

## Direction contract

THESIS: 以可盘点的整包数量为主，先筛选，再集中核对变动。
OWN-WORLD: 暖白底、瓷白卡片、莓墨正文、莓果选中与主操作；所有库存数量保持同一边线。
STORY: 管理员查看 221 色，跨筛选调整，查看完整清单后整批保存。
FIRST VIEWPORT: 紧凑页头与编辑入口；四列库存状态、五列两行颜色组；双列卡片；编辑时安全区上方固定确认托盘。
FORM: 用户指定双列文本台账与两组筛选，沿用已建立视觉系统；无随机方案、无色卡、无库存告警。
FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance

最小触控约 44px；0/1 包不变红。未盘点不同于零，直接输入可完成首次零盘点。保存结果未知时只核查/重试原批次，草稿不静默丢弃。真机测试由用户后续完成。

## 初版页面设计记录（2026-09-15，视觉已由下述选定方案替代）

本说明仅约束 `/admin/pages/store-bead-stock/index` 及其编辑、确认、历史和详情状态。页面属于现有 Ribbon Ledger 的 Operate 表面，复用 [DESIGN.md](../../DESIGN.md) 的颜色、字体、圆角和控件尺寸，不引入新的全局令牌或品牌方向。业务语义以[门店用豆库存规划](../../docs/01_requirements/store_bead_stock_plan.md)为准。

- **浏览层级：** 紧凑文本页头左侧为“用豆库存”及整包说明，右侧为“调整库存”。暖白背景上的瓷白卡片以细边线分区，不额外增加纹理、大型库存面板或装饰图片。色号先于数量，数字使用表格数字，单位“包”降一级；有独立色名时以辅助文字显示。
- **筛选结构：** 库存状态“全部 / 有库存 / 无库存 / 库存不足”始终四列完整展示；颜色分组“全部 / A / B / C / D / E / F / G / H / M”固定五列两行。两组各有文字标签、同尺寸控件和莓果实底选中态，不使用横向滑动隐藏选项。筛选下方给出当前与全部色数，浏览时右侧提供“调整记录”。
- **文本台账：** 221 色按当前筛选呈现双列卡片；320、390、768 宽度的本轮 H5 截图均保持双列。卡片以色号和整数包数辨识，不展示色块；0 包和 1 包没有红边、告警角标或提醒。未盘点直接显示文字，不转成 0；上方说明未盘点仅出现于库存状态“全部”。
- **集中编辑：** 页头动作切换为“取消调整”。调整原因与选填备注先于卡片网格，以浅粉区域收拢；备注的实际输入面完整收在圆角边界内，并与第一排库存卡保持间隔。卡片中数字输入独占一行，下方并排放置减号与加号，再显示原值到草稿值的文字。零库存减号使用可辨识的浅色禁用态。筛选仍可切换，当前未显示的草稿保留；固定底部操作区显示全批已修改色数和“确认调整”。
- **二次确认：** 独立确认状态展示所有已修改颜色，不受当前筛选限制。色号及增减说明在左，修改前后包数在右；顶部增加与减少分别汇总，首次盘点单独列出。原因与备注跟在清单之后，底部并排“返回修改 / 确认保存”，保持明确的主次层级。详情复用这一变更清单，补充时间、操作人和原因；历史列表以整批记录为可点击对象。
- **状态与恢复：** 真实读取中、读取失败和禁用分别表达，失败时显示可行动文案与刷新入口，不残留“正在读取”的摘要。空结果提供“查看全部颜色”。保存中保留可辨识的禁用按钮；结果未知时冻结编辑并核查原批次，冲突时保留草稿后核对最新库存。历史详情失败的“重试”重新读取同一详情，列表失败才重载列表。

## 布局与交互边界

正文复用既有中文字体与莓墨层级。主要筛选、数字输入、加减及底部按钮沿用控制高度；本轮 H5 截图中主要可用按钮约为 44px 或以上。页面源码在编辑和确认状态预留底部操作区及安全区空间，宽屏限制内容宽度且不增加卡片列数。固定操作区、键盘弹起和滚动末尾在微信真机上的表现仍需设备验证，不能由 H5 截图推定。

双列、无色块、无库存提醒和两阶段整批保存是本页面的已确认设计约束，不外推为商品库存、商城颜色选择或其他管理页的规则。此次没有新增图片资产，也没有新增动效系统。

## Product Design 选定修订（2026-09-15）

用户选定本轮 Option 3「柔粉分区」，并明确要求变更清单保留“左侧色号及增减、右侧前后数量”的形式。本次以此替代上文初版的独立双列卡片和默认上下排列加减控件。当前视觉约定以 [DESIGN.md](../../DESIGN.md#store-bead-stock-ledger局部表面) 和 [本轮检查](../../docs/08_frontend/qa/store-bead-stock-soft/review.md) 为准：两维筛选收拢到浅粉区域；双列台账按可见行交替底色；常规宽度横向加减，≤360px 数字独立成行；确认逐条白色记录同时显示增减量及前后值。未增加绿色／黄色点缀或库存告警。仅用户已确认此前功能，新视觉真机检查由用户继续完成。
