# Phase 5 补漏学习笔记：账号密码注册

> 状态：**工程实现与微信开发者工具 Functional 已全部完成。** 本补漏项只接入现有用户名/密码注册，不包含验证码、找回密码、邮箱验证、微信登录、OAuth、自动登录或角色选择。

## 1. 规划与边界

注册纵向链路固定为：

```text
登录页注册入口
  → 保留白名单 redirect
  → 受控注册表单与客户端即时校验
  → AuthContext.register()
  → AuthApi POST /auth/register
  → UserOut Runtime Guard / 白名单投影
  → 明确注册成功态
  → 用户主动进入登录页
```

后端注册成功只返回 `UserOut`，不返回 Token。因此前端不能把“创建用户”伪装成“已登录”，也不能自行构造 Session。注册用户固定为普通用户、正常状态；角色和状态仍以服务端响应为准。

字段按实际 Pydantic/OpenAPI 契约处理：username 3–32、password 8–64、nickname 1–32、phone 为 `^1[3-9]\d{9}$`。确认密码只存在于客户端，不进入 Endpoint 请求。用户名、昵称和手机号去除首尾空白；密码保持用户原始输入，不 trim、不写 URL、不持久化。

## 2. 成功、失败与结果未知

- `1001`：用户名已存在；
- `1007`：手机号已存在；
- `422`：请求字段不符合后端 Schema；
- 成功：只进入成功态并显示服务端返回的用户名，用户点击“去登录”；
- network/timeout/cancel、HTTP 非契约响应、成功信封形状损坏或 5xx：无法证明 POST 是否已提交，显示“注册结果暂无法确认”，不自动重发，先引导用户尝试登录；
- 同一次进行中的提交使用同步 ref 门闩防止快速双击发出两次 POST。按钮禁用是 UX，ref 才覆盖同一事件帧内 React state 尚未提交的窗口；这两层仍不等于服务端幂等。

登录与注册之间只传递 `parseLoginRedirect()` 接受的固定路径；动态详情、外部 URL 和任意内部路径继续被拒绝。注册表单不把用户名或密码放入 query，成功后也不自动携带密码登录。

## 3. 知识点

### 3.1 创建身份不等于建立会话

注册响应是用户资源，登录响应才包含 access/refresh token。客户端必须尊重响应能力边界，不能因为注册成功就凭空构造认证状态。

### 3.2 POST 超时的关键问题是“结果未知”

客户端没收到成功响应不代表服务端没有创建用户。自动重试可能得到 `1001/1007`，甚至在没有唯一约束的系统中制造重复资源。恢复动作应先查询或尝试登录，而不是立即再 POST。

### 3.3 React state 不是同步互斥锁

连续点击可能在 `setSubmitting(true)` 生效前共享同一旧闭包。涉及非幂等写请求时，需要同步 ref 或独立用例对象锁住进行中的 Promise，不能只依赖 disabled 属性。

### 3.4 确认密码是客户端字段

它用于减少输入错误，不属于后端注册资源。Endpoint 白名单必须只发送 username/password/nickname/phone，避免把 UI 辅助字段扩散到协议层。

### 3.5 生成类型仍不能校验 HTTP 数据

`UserCreate` 提供编译期请求类型；成功响应仍按 `unknown` 处理，并通过既有 `parseUserProfile()` 重建不含 password 的白名单对象。

### 3.6 文档与实际 Schema 冲突必须显式记录

本次审阅发现 `user_api.md` 曾写 username 只能使用字母、数字和下划线，但实际 `UserCreate` 和 OpenAPI 只有长度约束，没有 pattern；API 文档已同步为当前事实。前端不额外拒绝字符；若要收紧，必须先修改后端 Pydantic Schema、测试、OpenAPI 和 API 文档，再同步前端，不能只靠客户端校验充当安全边界。

## 5. Functional 清单

1. Guest 登录页能进入注册页；
2. 从订单/管理固定登录入口进入时，登录 → 注册 → 登录仍保留原 redirect；
3. 必填、长度、手机号和两次密码不一致在本地阻止提交；
4. 合法新用户名与手机号注册成功，页面不自动显示已登录；
5. 点击“去登录”，用新账号密码登录成功并回到原固定目标；
6. 重复用户名显示 `1001` 对应提示；
7. 重复手机号显示 `1007` 对应提示；
8. 快速连续点击只产生一条用户；
9. 断网/超时时显示“结果暂无法确认”，不会自动再次 POST；
10. 密码不出现在 URL、Storage、页面成功态或日志中。
