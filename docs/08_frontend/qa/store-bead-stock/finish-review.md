## 4. Material findings / exact fixes

### F1 · 错误、加载和禁用状态未清楚分开（P2）

证据：`load-error-390.png` 已显示响应失败，但列表摘要仍写“正在读取库存…”，右上角只剩无字的空按钮框；`edit-320.png` / `edit-390.png` 的零库存减号也近乎消失。用户会误以为请求仍在继续，无法辨认被禁用的动作。

位置：`index.tsx` 的摘要（当前约 83 行）以 `loaded` 判断“正在读取”，未检查 `loading`；`use_store_stock.ts` 的 `load()` 直接展示底层 Error.message。页面样式对禁用态仅叠加透明度。

修复：只在实际 loading 时显示读取文案，未成功且已失败时改为“库存暂不可用”或隐藏重复摘要；将不合契约等底层错误映射为可行动的门店语言，例如“库存读取失败，请刷新重试”，保留技术细节在适当的开发诊断边界；针对本页禁用 header / step / footer 控件明确设置可读前景与浅色背景，避免默认禁用样式把文字洗成白色。确认保存中的两个禁用按钮也沿用同一可辨识策略。

验收：重新打开错误截图，失败不再伴随虚假的读取状态，调整按钮文字可见；编辑截图中零库存的减号仍可辨识，同时视觉上明确不可用。

### F2 · H5 备注框内层溢出外框（P2）

证据：两张 edit 截图的白色备注框内层伸出其圆角边框底部，原生 resize 手柄落到外框之外，和下方色号卡片几乎相接。该边界破坏了输入区域与库存控件的分组，窄屏更明显。

位置：`index.scss` 的 `&__note` 同时在 Taro 外层设固定高度、padding 与 border，未约束 H5 生成的实际 textarea；原因区与卡片网格之间没有显式间距。

修复：核对 Taro 渲染结构，以本页作用域类选择器将 H5 内层 textarea 设置为 border-box、适配外层可用宽高、继承字号并关闭 resize，避免内外层双重 padding / 高度；保持微信端字段尺寸。为原因区和库存网格增加一段明确的小间距。

验收：320 / 390 的备注框完整包住实际输入面，没有向卡片伸出的白色方块或拖拽角，下方第一排库存保持独立。

### F3 · 记录详情失败后的“重试”执行了另一项操作（P2）

证据来自源代码：`StockHistory.open(id)` 失败提示“记录详情读取失败，请重试”，但共用错误按钮只增加 `retry`，触发的 effect 调用 `history(page)`，并不重取失败的 detail。列表重载成功后错误消失，用户仍没得到要求打开的记录。

位置：`index.tsx` 的 `StockHistory`，当前约 135–151 行。

修复：保留失败的详情 ID 或明确的重试操作；详情失败点击重试应调用该 ID 的 `detail`，列表失败才重载当前列表页。用行为测试验证详情首次失败、点击重试、同一详情成功可见，不需要额外视觉方案。

验收：提供定向测试结果；成功历史和详情截图的既有版式应保持。
