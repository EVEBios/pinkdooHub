# P1.3 资金结果检查（2026-09-14）

范围：当前仓库实现及隔离 SQLite／组件测试；不代表目标环境、微信真机或 Release Gate 验收。

## 交付内容

- 代客钱包下单只产生一条订单资金结果，展示扣款和当时余额。普通支付结果不重复生成。
- 钱包退款／门店登记线下退款产生订单结果，合并关联桌台关闭；单订单付款及退款均未读时仍只计一件。线下文案不保证系统已验证资金到账。
- 独立余额调整按每笔流水生成一件，新增 wallet_unread 汇总，首页、会员及会员 Tab 使用同一来源。列表不读，精确详情完整展示后确认，已读保留历史。
- 余额列表只有全部调整／新结果两个筛选；详情与资金明细间可导航，沿用原有页面与按钮样式，按钮保持显式间距。完整原因读取自顾客原本可见的账本字段，不复制内部备注。

## Review

- 分层：资金 Service 在既有事务内写 AttentionRepository；AttentionService 经 Repository 查询结果与原始流水，API 只校验、授权与序列化。未新增业务 Service 互调。
- 原子性：结果写入之后注入失败，验证余额、支付、结算、订单、库存、占台、退款和事件均回滚；幂等重放保持原结果。读取与已读不发起资金操作。
- 归属：按事件接收者及原始流水钱包双重限定。只有本人可读取／确认；管理员不能读顾客结果，禁用者合法纠错仍落结果但不放宽认证。错误引用不能泄露其他钱包。
- 数据：独立调账事件键唯一引用不可变流水，不新增 FK 或列。列表只查询事件并稳定分页，详情通过流水主键读取；没有列表逐行流水查询。真实 MySQL 索引与并发证据待 P1.4。
- 前端：校验确切事件、结构化流水、金额守恒与角色计数，缺失汇总不伪装成零；隐藏／换身份后的过期响应不误清。已读失败保留重试。历史金额明确标注本笔发生时。
- 兼容：依赖已有 M13；金额原因从原始账本读取，256 字原因不会截断。新字段／枚举要求前后端配套更新；旧后端回滚需兼容新增事件类型，不删除事件或账本。
