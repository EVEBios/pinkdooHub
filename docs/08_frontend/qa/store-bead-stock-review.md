# P2.4 门店用豆库存交付与验收记录

2026-09-15。仓库实现与隔离自动化完成；微信真实手机由用户后续验收。本记录不代表正式支付、持久 MySQL 迁移或发布通过，不改变现有 Release Gate。

## 功能交付

入口：管理员店铺工作台 → 商品与库存 → 用豆库存。普通入口没有红点或补货数量。独立记录未拆封整包，不联动商城 10g 库存、订单、退款、桌台消耗或通知。

- 221 色，现有 A～H、M 目录；双列色号/名称卡片，无色卡。四项库存状态与五列两行颜色分组独立取交集，无水平滑轨。
- 未盘点与 0 包区分；有库存含 1、无库存仅 0、库存不足含 0/1。0/1 不变红、不产生提醒。
- 浏览无加减；编辑前刷新、包数输入独占一行，加减控件分布其下。草稿跨筛选保留，按进入编辑时的已提交数量筛选，正在修改的卡片不突然消失。
- 确认页展示所有变更，增加、减少、首次盘点分别统计。再次确认才提交，首次 0 盘点有效；整批原子保存、版本冲突保留草稿、未知结果复用原请求核查/重试。
- 调整原因/选填备注与按批次查看记录；详情读取失败会重新读取原详情。没有修改/删除历史入口。
- 原生离开草稿提示、身份切换卸载旧工作区、后台返回浏览刷新；不承诺关闭小程序后的草稿恢复。

## 数据库现场与迁移边界

M15 文件只新增门店余额、批次、逐色流水三表，不回填包数；有历史时降级拒绝执行。CI 隔离迁移链与测试入口已更新至 M15，但本机未完成真实 MySQL 从旧结构到 M15 的迁移演练。上线前必须另行运行该门槛，不能用离线 SQL 检查顶替。

本任务没有运行持久库的迁移/回滚命令。只读检查 `/Users/shenyijie/Projects/pinkdooHub/db.sqlite3` 发现本地 development 已有三张新表，与既有启动自动建表机制一致；目录 221 色，三个新表均为 0 行，唯一索引和四个 RESTRICT 外键存在。没有人为初始化虚构库存，也没有写测试库存至该本地库。

该 SQLite 表的 `store_bead_stock_entries.color_code` 保留开发过程中自动建表时的 `VARCHAR(32)` 声明；最终模型与 MySQL M15 为 `VARCHAR(50)`。SQLite 对二者使用同一 TEXT 亲和性、不按该数字限制文本长度，因此当前 221 色功能无需数据转换即可使用；仍不能把本地建表状态当作与正式 M15 元数据一致的证据。本轮未为统一声明重建本地表；未来若需收敛元数据，先备份并按持久迁移规则单独授权。

未执行真实 MySQL 迁移、微信上传/发布或 Release Gate 操作。迁移与降级要求见[迁移流程](../../07_process/database_migration_workflow.md)。

## 微信 WXSS 编译兼容修复（2026-09-15）

用户在开发者工具发现 `> :first-child:not(:last-child)` 编译失败。本轮用已安装微信开发者工具的 `wcc-exec/wcsc` 复现相同报错；移除后进一步发现页脚 `> * + *` 也不被该编译器接受。

页头文本容器改用显式 `bead-stock__header-copy` 类；页脚以本页明确的次要按钮/数量文案与主按钮相邻类选择器保留间距。没有改变库存、筛选、确认或保存行为。

验证：原有微信 watch 已更新实际 JS/WXSS；将 `admin/pages/store-bead-stock/index.wxss` 及其依赖 `admin/sub-vendors.wxss` 一起交给微信原生样式编译器，退出码 0。模块 3 suites / 11 tests 通过，包含新增选择器回归和本机微信编译器验证；TypeScript、定向 ESLint、Stylelint 及 diff 检查通过。没有安装微信编译器的环境会跳过该原生专项，可通过 `WXSS_COMPILER` 指定编译器路径；静态回归仍执行。

这补充了之前 Taro 构建及包体检查不覆盖 WXSS 原生语法解析的缺口，不代替手机运行验收。没有新增长驻资源；测试临时目录已回收，现有开发者工具与 watch 未停止。
