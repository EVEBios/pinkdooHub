# 订单与桌台站内交接 P1.2 验收记录

日期：2026-09-14。范围：仓库实现、隔离测试与 H5 页面验证。未迁移持久环境、未上传或发布，不构成 Gate A 放行证据。

## 业务与交互

- 管理员订单入口显示普通待付款与待履约数量；仍在付款时限内的占台订单只进入桌台提醒，避免两处重复催办。首版直接提醒全部有效待付款桌台，顾客不增加“我已付款”操作。
- 人工或余额付款生成顾客订单结果；涉及桌台启动或关闭的信息合并到该结果。订单完成同理，不额外制造同一次业务操作的桌台红点。
- 独立付款超时、计时到期和管理员释放按桌台会话生成结果。无需账号的直接开台不生成顾客提醒。
- 顾客首页与会员中心显示订单、桌台事项，会员 Tab 汇总两者；预约入口继续使用原提醒。计数按订单或会话去重，而非逐条累加历史事件。
- 结果内容先完整呈现，再按此次返回的精确事件 ID 回执已读；保留内容供复看。隐藏页面、切换身份、旧请求返回或新事件到达不会误清其他结果。
- 历史桌台入口定位到指定会话并验证归属；同一桌台有新开台时，旧结果仍展示旧会话。超时提示说明当时未付款，并引导查看关联订单最新状态。

权威规则见 [提醒需求](../../01_requirements/attention_module.md) 与 [提醒 API](../../03_api/attention_api.md)。
