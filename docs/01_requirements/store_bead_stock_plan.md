# P2.4 门店用豆库存管理规划

日期：2026-09-15。状态：仓库实现完成；真机验收与持久环境迁移待执行。用户已授权按本方案完成实现，视觉先交付再调整。本文为本模块业务规则，自动化及视觉证据见[验收记录](../08_frontend/qa/store-bead-stock-review.md)。

## 1. 已确认边界

- 新增门店用豆独立库存，按颜色维护未拆封整包数量，最小调整单位为 1 包，只允许非负整数。
- 拆开一包即由店员记录减少 1 包；开台、付款或计时结束不自动推算消耗。开封后的散豆不计入本模块。
- 商城继续按既有 10g 颜色销售单位扣减、取消恢复与退款恢复；两份库存不自动同步，也不把既有克数余额直接解释成包数。
- 共 221 色，复用全局颜色身份，页面仅显示色号/名称，不展示色卡图片或 HEX 色块。
- 手机每行两个颜色；默认无加减号，点击“调整库存”后统一进入批量编辑。确认时列出全部发生变化的颜色，再次确认后保存。
- 筛选分为两个独立维度：库存状态（全部、有库存、无库存、库存不足）和颜色分组（全部及实际色号首字母）。库存不足为已盘点且小于等于 1 包。
- 当前不做库存主动提醒：无首页红点/数字角标、无低库存红边或警示底色、无补货通知；只通过库存状态筛选查看对应颜色。

## 2. 页面与视觉

沿用项目暖纸白背景、瓷白表面、莓墨正文与莓果主动作，不采用参考图紫色主题。该页定位为管理端“用豆库存”，不提供顾客入口；库存多少不改变卡片边框或背景颜色。正常的输入校验错误仍沿用项目错误反馈规范。

| 区域 | 建议布局与内容 |
|---|---|
| 页头 | 标题“用豆库存”；短说明“只记录未拆封整包”；“调整库存”入口 |
| 列表概览 | 普通文字显示当前筛选结果数量；未盘点数量单独用普通文字说明，不设置告警数字 |
| 库存状态筛选 | 第一组：全部、有库存、无库存、库存不足；手机等宽四列一行完整展示，组内单选 |
| 颜色分组筛选 | 第二组：全部、A、B、C、D、E、F、G、H、M；手机五列两行完整显示，组内单选，不使用左右滑轨 |
| 颜色列表 | 两列紧凑台账，浅粉隔行底色与库存数量无关；色号如 A1、数量如 3 包；名称与色号相同时只显示一次 |
| 编辑卡片 | 上方色号，下方减号/整数输入/加号；另示“原 3 包 → 现 2 包”，触控区域不挤压 |
| 底部操作区 | 编辑时固定显示“已修改 N 色”和“确认调整”；兼顾 iPhone 安全区及列表底部留白；可取消调整 |

当前仓库 MARD 目录的分组为 A 26、B 32、C 29、D 26、E 24、F 25、G 21、H 23、M 15，共 221 色。参考图的 L 不属于当前目录，不额外添加；排序沿用目录的自然编号顺序（A1、A2、…、A10），不按字符串把 A10 排在 A2 前面。色号搜索可作为辅助建议，不影响以上核心布局。

所有库存条目统一使用正常样式，数量直接显示“0 包”“1 包”等，不额外加“需补货”警示标签或红色标记。编辑中的变动用原值/新值说明；首次录入的卡片显示“未盘点 → N 包”。两组筛选采用相同的莓果选中态，“库存不足”不使用特殊红色样式。

## 3. 两组筛选规则

第一组命名为“库存状态”，将用户的“没库存”统一为“无库存”：

| 选项 | 范围 |
|---|---|
| 全部 | 所有颜色，包含未盘点项 |
| 有库存 | 已盘点且至少 1 包 |
| 无库存 | 已盘点且恰好 0 包 |
| 库存不足 | 已盘点且小于等于 1 包，即 0 包和 1 包 |

“有库存”与“库存不足”在 1 包时有交集，“无库存”也是“库存不足”的子集，这是有意的业务定义；四个选项是四种查看方式，并非互斥的库存分类。“未盘点”不等于 0，不纳入后三个筛选；只在库存状态为“全部”时展示（仍受颜色分组限制）。

第二组命名为“颜色分组”，按实际目录提供全部、A、B、C、D、E、F、G、H、M；“A–M”表示现有色号范围，不虚增目录不存在的 I/J/K/L。

- 管理员首页“商品与库存”组增加普通“用豆库存”入口，不携带红点、角标或补货数量。
- 默认两组都选“全部”；组内单选、组间取交集。例如“有库存 + A”只显示 A 组至少 1 包的颜色，“库存不足 + B”只显示 B 组 0/1 包颜色。
- 每组“全部”只重置本组，不改变另一组；点击已经选中的选项保持原选择，需要取消限制时选择本组“全部”。切换筛选立即生效，不额外增加“应用筛选”。
- 列表用普通文字显示“当前 N 色”；空结果显示“没有符合条件的颜色”，提供重置全部筛选的普通操作。
- 编辑中的库存状态匹配使用进入编辑时的已提交快照，按当前两组选择筛选；草稿数量改变不导致卡片突然消失。成功保存后以最新已提交数量重新筛选，保留两组选择。
- 不生成库存提醒事件或已读状态，不接入首页提醒汇总、推送或专用告警轮询；本期无需设计提醒出现/消除流程。

## 4. 调整与二次确认

1. 默认浏览当前库存。点击“调整库存”获取最新快照，出现所有可见卡片的加减号和整数输入框。
2. 可连续调整多色，切换任一库存状态或颜色分组都保留整批草稿；回到原数量的已盘点颜色移出修改清单。禁止负数、小数及无效输入；0 包时禁用减号。直接数字输入支持快速盘点和大批补货。
3. 无变化时底部按钮禁用；有变化时显示“确认调整（N 色）”，数量包含当前筛选外的变动。未盘点录入 0 也属于有效首次盘点，不能被当成零变化忽略。
4. 点击后进入专门的确认面板/确认页，列出全部变动，内容可纵向滚动，固定按钮不遮挡最后一行。避免把长清单塞进原生简单弹窗。
5. 每项采用独立记录行，左侧显示色号及增加/减少包数，右侧显示“原库存 → 新库存”；首次盘点明确标注，不能伪造已知原库存。显示修改色数、分别增加和减少包数，不用净变化掩盖双向调整。整批可选择调整原因，默认“库存盘点”，可选“补货入库/开包领用/其他”，备注按需填写。
6. 二次确认按钮用“确认保存”（4 个汉字），返回按钮用“返回修改”，回去继续编辑不丢草稿。只有“确认保存”向服务端提交。
7. 成功后提示本次已更新 N 色，恢复浏览状态、刷新包数和当前筛选结果；保存逐色流水，提供本次调整详情。无需再增加第三次确认。
8. 放弃或离开存在草稿的页面时提示保留编辑/放弃修改；前后台切换保留当前草稿，但不承诺首版跨设备或关闭小程序后恢复。身份退出或改变时清除旧账号草稿。

示例：A1 3→2（−1 包）、B6 0→5（+5 包）、M3 2→1（−1 包）。确认清单显示 3 色，增加 5 包、减少 2 包；成功后 B6 不再匹配“库存不足”，M3 匹配“库存不足”，两者卡片均保持正常边框。

## 5. 保存一致性与数据

现有 Inventory 属于商品销售库存，现有接口是单商品/单颜色调整，不能直接循环请求 221 次实现批量保存。新模块复用既有分层、权限、审计和幂等模式，但余额与流水需要独立存储；全局 BeadColor 继续只负责颜色身份。

- 建议独立门店颜色余额（颜色关联、未盘点/已盘点、整数包数、版本/更新时间）、批次记录及不可变逐色流水。实际表、字段、接口与迁移编号见上述权威文档。
- 本期固定现有门店的一份 221 色台账，不预建多门店、多个仓库、采购审批或供应商模块。所有 ADMIN+ 共用这份库存；商品启用/禁用不改变门店库存及其筛选归属。
- 整批提交只带变更颜色及其读取版本/原值、新数量和原因；由服务端计算变化量并校验，不能信任客户端传入的变化流水。
- 同一批次在一个事务中按稳定颜色顺序加锁、复核版本、写余额、写流水和审计。任一项不合法或发生冲突，整批不保存，不允许部分成功。
- 若另一位管理员已改动待提交颜色，返回冲突颜色和最新数量；保留用户草稿供重新核对，重新展示确认清单，不悄悄覆盖也不自动合并。未被本次修改的颜色变动不应阻挡整批。
- 重复点击/超时重试复用同批请求身份，不重复加减。结果未知时优先核查原批次，不制造新批次重新提交；明确失败时保留草稿。
- 流水记录操作人、时间、原因、逐色原值/新值、整数包单位和批次关联；首次盘点包括确认 0 包的记录。纠错生成新记录，不改删历史。
- 已有商城余额、订单数量快照、取消/退款恢复和原库存流水保持原单位与含义。门店包库存不从既有克数自动换算，也不把 221 色全部预填某个虚构包数。
- 新独立库存首次需真实盘点；未录入项显示未盘点，允许分批完成，不将未知数量作为真实缺货。

## 6. 分步交付与验收建议

| 步骤 | 交付 |
|---|---|
| P2.4-A 规则与视觉确认 | 本规划；确认默认浏览、编辑、长变更清单、空筛选与首次盘点布局 |
| P2.4-B 库存与批量保存 | 独立余额/批次/流水、列表/提交/原批次结果查询、权限/并发/幂等及迁移演练 |
| P2.4-C 界面与筛选 | 双列 221 色、四项库存状态/两行颜色分组筛选、批量草稿和二次确认；不含库存提醒 |
| P2.4-D 联合验收 | 自动化、开发者工具及 iPhone；真实包数由店员盘点后按授权导入 |

重点验证：有库存含 1 包、无库存仅 0 包、库存不足含 0/1 包；未盘点只归入库存状态“全部”；两组交集及独立重置；空结果；保存后 2→1、1→0、1→2 的筛选匹配正确；所有数量均无红边/红点；修改跨两组筛选保留；改回原值不提交；首次盘点 0 可提交；全部变更在确认清单可见；取消不改库；混合加减整批原子提交；双管理员冲突；重复点击和断网重试不重复入库；权限撤销后无法保存；商城下单/取消/退款完全不影响门店包库存。手机在 320/390 宽度保持双列、两组筛选完整且没有横向溢出，键盘及底部安全区不遮挡按钮和最后一行；221 色渲染与筛选响应需实测。

实现提供独立余额、批次及流水表（M15）和管理 API，详见[接口契约](../03_api/store_bead_stock_api.md)与[数据库设计](../02_database/database_design.md)。持久环境迁移仍需按项目流程另行授权；本轮未执行持久数据库迁移，未启用微信推送。真实包数由店员首次盘点，不自动导入。
