# 商品模块（Product Module）

> **Last Updated:** 2026-09-07
> **当前状态：** Phase 4.1 固定套装已实现；M6 自选颜色套装的仓库实现、客户端接入与本地回归已完成，离线迁移仍须通过一次性 MySQL 0→6 门槛，不能据本文档视为已部署。

---

## 1. 模块目标

商品模块负责管理拼豆店提供的服务与商品，包括拼豆体验和拼豆套装的管理，并为订单模块提供商品信息。

该模块面向两类用户：

- 普通用户：浏览商品、查看详情
- 管理员：管理商品信息

---

## 2. 商品类型

系统中的商品分为两类：

### 拼豆体验

用户购买的是指定时长的拼豆体验。

| 示例 | 时长 | 人数 |
|------|------|------|
| 工作日单人 | 1 小时 | 1 人 |
| 工作日双人 | 2 小时 | 2 人 |
| 周末单人 | 2 小时 | 1 人 |
| 周末双人 | 3 小时 | 2 人 |

体验商品包含：

| 属性 | 说明 |
|------|------|
| 体验时长 | 以小时为单位 |
| 适用人数 | 单人 / 双人 |
| 日期类型 | `weekday` 工作日 / `holiday` 节假日；Reservation N1 当前映射为周二至周五 / 周六日，周一固定店休 |
| 售价 | 不同组合不同价格 |

### 拼豆套装

拼豆套装分为两种业务形态，均继续使用 `product_type=kit`，由不可变的 `kit_kind` 区分：

| `kit_kind` | 含义 | 购买方式 |
|------------|------|----------|
| `fixed` | 已搭配好的固定套装 | 按“套”购买；与 M6 之前的 Kit 完全兼容 |
| `color_selectable` | 自选拼豆颜色套装 | 从全局 221 个颜色槽中选择该商品已启用的颜色；每个数量单位为 10g |

固定套装示例：

| 示例 |
|------|
| 新手体验套装 |
| 动漫主题套装 |
| 节日限定套装 |

`fixed` 套装内容固定，不支持用户自由组合；`color_selectable` 套装允许在同一商品内选择多种颜色。两种形态创建后都不得互相转换，避免库存、历史订单和展示结构失去语义。

套装包含：

| 属性 | 说明 |
|------|------|
| 套装名称 | 展示名称 |
| 套装介绍 | 详细描述 |
| 套装图片 | 多张展示图 |
| 售价 | `fixed` 为每套价格；`color_selectable` 为统一的每 10g 价格，所有颜色相同 |
| 销售单位 | `fixed` 沿用每套；`color_selectable` 固定为 10g |
| 库存 | `fixed` 按商品保存；`color_selectable` 按“商品 × 颜色”分别保存，颜色库存不跨商品共享 |

M6 全局预留 `slot_no=1..221` 的 221 个 `bead_colors` 颜色槽。颜色名称和业务编码允许暂时为空，待详细清单提供后补齐；只有在具体 `color_selectable` 商品中启用的颜色才可见、可下单。每个自选颜色商品拥有自己的 221 条商品颜色关联，初始全部禁用且库存为 0。

## 4. 商品信息

每个商品包含以下信息：

### 基础信息

| 字段 | 说明 |
|------|------|
| 商品名称 | 展示名称 |
| 商品类型 | 体验 / 套装 |
| 商品描述 | 详细说明文本 |
| 商品图片 | 主图 + 详情图 |

### 价格信息

| 字段 | 类型 |
|------|------|
| 商品售价 | Decimal(10,2)，单位：元 |

### 库存信息

| 商品类型 | 库存策略 |
|----------|----------|
| 拼豆体验 | 无需库存，不限制数量 |
| `fixed` 拼豆套装 | `product_kits.stock` 保存按套库存，售卖时扣减 |
| `color_selectable` 拼豆套装 | `product_kit_colors.stock_units` 保存该商品该颜色的 10g 单位库存；不同商品即使指向同一全局颜色槽也不共享余额 |

### 状态信息

| 状态 | 说明 |
|------|------|
| draft（草稿） | 编辑中，用户不可见 |
| online（上架） | 已发布，用户可见可购买 |
| offline（下架） | 已下架，用户不可见 |

## 5. 商品生命周期

```
草稿 ──→ 上架 ──→ 下架
  ↑                 │
  └───────←─────────┘
        (重新上架)
```

| 流转 | 触发角色 | 说明 |
|------|----------|------|
| 草稿 → 上架 | 管理员 | 发布商品 |
| 上架 → 下架 | 管理员 | 下架商品 |
| 下架 → 上架 | 管理员 | 重新上架 |

## 6. 商品图片

一个商品可以拥有多张图片：

| 类型 | 说明 | 数量 |
|------|------|------|
| 主图 | 列表展示用，封面图 | 1 张 |
| 详情图 | 详情页展示用 | 多张 |
| 展示图 | 附加展示 | 多张 |

自选颜色的色板图片不属于某个 Product 的公共图库，而属于全局颜色定义；冻结字段为可空 `BeadColor.swatch_image_url`，缺图时客户端使用颜色元数据或统一占位样式。实物照片仍建议使用一致光照与构图的 192×192 或 256×256 sRGB WebP，并由对象存储/CDN 按需加载，不打进小程序包。

按 221 张计算的资源体积估算如下；这里的 KiB/MiB 使用 1024 进制，只统计图片本体，不含极少量 HTTP/清单开销：

| 单张目标 | 221 张合计 | 用途判断 |
|----------|------------|----------|
| 8 KiB | 约 1.73 MiB | 构图简单、压缩充分时可达到 |
| 25 KiB | 约 5.40 MiB | 推荐日常目标，能兼顾 256×256 色板细节与加载速度 |
| 64 KiB | 约 13.81 MiB | 建议作为软上限，导入时提示优化 |
| 128 KiB | 约 27.63 MiB | 建议作为单张硬上限，超过则拒绝导入 |
| 2 MiB（复用现有 Product 单图上限） | 442 MiB | 明显不适合 221 色批量资源 |

2026-09-07 用户指定的 [MARD 221 标准色卡](https://peiseka.com/pindouseka.html) 来源页并不提供 221 个独立图片文件，而是以 CSS `background-color` 根据 HEX/RGB 绘制纯色色块。项目已抓取 A1–M15 共 221 项，逐项确认 CSS RGB、展示 RGB 与 HEX 一致且无重复，冻结来源 HTML SHA-256 和清单。随后用标准库确定性生成 256×256 sRGB PNG：221 张内容总计 **128,325 bytes（约 125.3 KiB）**，远低于原预算；本地运行文件仍放在忽略目录 `uploads/products/`，不进入小程序包或 Git。

初始化使用 `scripts/local/import_mard_bead_colors.py`：默认 dry-run，显式 `--apply --confirm-local-only` 后才生成图片并更新本地 M6 SQLite；写库前建立一致性备份，元数据事务失败会回滚并删除本轮新建图片，已有冲突或 Online 商品引用时 fail closed，完全相同重放零写入。该本地工具不代替生产对象存储/CDN 发布，也不能应用 MySQL。
