# Gate A 内部测试运维与事故规则

> **Status:** Frozen for pre-ICP Gate A preparation
> **Owner:** Yijie Shen
> **Last Updated:** 2026-09-02
> **Scope:** 微信开发版/体验版受邀内部测试；不适用于 Gate B 公开发布

本文关闭不依赖域名备案的测试运营输入。实际体验版仍须在备案、DNS、HTTPS、微信
合法域名和真机网络全部通过，并取得单独上传授权后才能产生；本文不构成上传、分发、
提审或公开发布授权。

## 1. 测试人员与访问边界

- 初始测试人员只有项目负责人 Yijie Shen；新增人员必须先进入受控 allowlist，再由
  项目负责人逐个邀请。测试人员的微信身份、手机号和账号凭据只保存在微信平台或
  私密运营清单，不进入仓库、Issue、日志、截图文件名或 Release Record。
- Gate A 只使用受控账号密码和合成业务数据。管理员初始化身份是唯一已批准的运维
  身份；普通业务数据不得使用真实客户资料。
- 版本名称、项目描述和测试说明必须包含“Gate A 内部测试、受邀、不可公开”；不得
  声称已经提供微信登录、微信支付、线上商业收款或公开服务。
- Gate A 的 `Pending → Paid` 只由 ADMIN+ 人工推进，用于验证订单状态闭环，不代表
  真实支付结果。

## 2. 反馈入口与信息分级

- 普通缺陷、界面和流程反馈使用
  [EVEBios/pinkdooHub GitHub Issues](https://github.com/EVEBios/pinkdooHub/issues)；Issue
  只允许合成账号角色、版本、设备型号、复现步骤和脱敏截图。
- 密码、Token、手机号、私钥、连接串、个人资料、完整请求/响应和数据库内容禁止进入
  Issue。此类内容只通过项目负责人已有的私密联系渠道报告；仓库只记录脱敏事件 ID、
  严重级别、时间和处置结论。
- 缺陷严重度：P0 为凭据/越权/数据破坏/无法恢复；P1 为核心业务、HTTPS、登录或
  库存/订单阻断；P2 为有绕行方案的功能问题；P3 为视觉或低影响问题。
- P0 立即停止测试并保持 No-Go；P1 在下一个测试会话前关闭或形成严格风险例外；
  P2/P3 可以排期，但必须进入缺陷清单。

## 3. 测试窗口、停用与数据清理

- 每个体验版的测试窗口从微信平台记录的上传时间 `T0` 开始，默认持续 14 个自然日；
  延长必须新建 Release Record，写明新截止时间、未关闭风险和批准人。
- 到期或发生 P0 时先从微信测试 allowlist 撤销分发，再停止外部入口；来源 MySQL、
  Redis 和图片卷不在未备份或未授权时删除。
- 停用前生成最终一致备份、独立恢复验证和加密异机副本。停用后 30 日是 Gate A
  恢复观察期；期满后删除合成业务数据或持久卷必须再次确认精确目标、备份、影响和
  授权，当前工具不提供自动删库/删卷命令。
- Backup、Restore、Bootstrap、代表性数据、韧性演练和 Release Record 属于脱敏审计
  证据，至少保留到 Gate A 决策结束后 90 日；若进入 Gate B，随当次数据保留 Review
  重新决定。

## 4. 事故联系人和响应

- 测试、技术、发布、安全和事故负责人均为 Yijie Shen，但发现、技术复核、风险接受
  和恢复授权必须分别记录时间，不能合并成一次笼统确认。
- P0 响应顺序固定为：停止分发/外部入口 → 保全日志和只读快照 → 撤销相关会话或
  Secret → 判断前滚或恢复 → 独立复核 → 更新风险与测试人员。不得先删日志或盲目重跑。
- 数据恢复只允许项目负责人对精确 Backup ID、目标环境、预计丢失窗口和停写状态做
  当次授权；恢复到来源卷、删除 Schema 或删除持久卷仍属于单独破坏性操作。
- 腾讯云主机不可达时使用管理电脑上的客户端加密异机副本；私钥不在服务器、仓库或
  备份目录中，恢复时由项目负责人从独立密钥目录提供。

## 5. 观察窗口

- 体验版每个测试会话开始前检查四项服务、readiness、磁盘和最近错误；会话结束后
  检查 4xx/5xx、请求时延、容器重启、磁盘增长和敏感日志扫描。
- P0/P1 修复后的新构建必须重新绑定 Git SHA、CI、OpenAPI、微信 Artifact checksum
  和环境；不能在开发者工具内手工改文件后继续沿用旧证据。
- Gate A 通过只授权受邀内部测试。提审和公开发布仍需要 Gate B 独立 Go/No-Go 与
  明确外部操作授权。
