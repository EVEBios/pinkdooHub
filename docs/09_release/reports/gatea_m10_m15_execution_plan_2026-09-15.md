# Gate A M10–M15 执行与验证计划

## 范围与前置条件

用户授权持续修复、提交、推送并按规划将 Gate A 迁移至 M15；需要密码时交接。当前持久状态以[已付款恢复记录](gatea_m9_paid_recovery_2026-09-15.md)及现场 records 为准。必须先完成 M9 的受保护恢复、验收、韧性、数据后独立恢复与 finalized lineage；不跨过失败记录直接迁移，不外推到共享或生产。

本分支以既有 M15 业务实现 `ec4c068` 为基础，合入 M9 恢复修复。没有因此认定已迁移或可以部署。旧 CI updater 与 source contract 只认识精确 M0–M9，新代码不能直接上传到现有发布器。

## 先完成发布工具能力

1. 冻结已 finalized M9 source 与 M15 target，区分历史 M9 验收和新候选验收；原证据格式继续可读。
2. 建立唯一权威 M0–M15 链与 M9→M15 执行契约，同时更新 source archive、镜像、迁移任务、operation、backup/restore、upgrade、stage、验收与 finalize 的支持范围。不能只改一个版本常量绕过拒绝。
3. 在一段停写窗口中逐个执行 M10–M15，逐步检查结构、Aerich 版本和保留数据。M15 代码只能在其完整依赖结构就绪后启动，不能在 M10/M11 中间结构上试运行最新版。
4. 原有字段按主键和原始列集合比较；M11 新增字段的合法默认值单独核验。新建表应为空，不回填旧提醒或虚构库存。现有全行 dump 摘要不能直接跨新增列比较。
5. 备份与独立恢复覆盖全部新增表、外键、索引及实际数据；Redis 仍以空实例验证。任一 DDL 部分完成时保留耐久记录，按实际结构前滚，不能假称事务回滚或重跑已完成步骤。
6. 先用本地合成存量数据做完整 M9→M15 演练，再运行当前候选自己的 CI。通过后才执行持久 Gate A 流程。

只修改发布编排时先运行受影响 release 测试；只修改模块时先运行本行测试与相关格式/类型检查。跨模块最终候选再运行一次完整后端、前端质量与生成契约检查。失败后仅重跑受影响范围；代码未变且证据有效时不重复全量测试或完整演练。

前端需要变更时按对应预约、桌台、提醒、跟进或门店库存测试目录验证。正式微信上传、灰度、发布以及真实微信资金不属于本次迁移；服务端上线不等同于小程序平台验收完成。

## 状态记录

本文件是执行计划，不是完成报告。M9 收口、M15 工具、隔离完整演练、CI、持久升级和数据后独立恢复分别留证；当前这些后续步骤尚未完成。

### 本地第一步：逐条迁移原语

单步任务现支持精确 M0–M15 文件清单，仍要求数据库恰好位于目标前一版，已在目标时只读 no-op。补齐双位数文件名后发现原清单比较混用了字典顺序与数字版本顺序，现只对文件集合比较使用同一排序，执行顺序继续来自固定清单。M10–M15 每个目标只传入该版本及更早文件，相关任务边界测试 `16 passed`。这一步尚未扩展 stage/backup/upgrade/finalize，源码前置门槛仍拒绝部署 M15；不应单独发布该工作分支。

M10 无套餐预约与 M11–M15 的现有迁移契约定向检查另有 `18 passed`（1.06 秒）；本轮没有重复全后端或前端套件。M9 已推进到 G 管理员 TTY 验收边界，具体状态见上述已付款恢复记录。

### 本地第二步：跨版本内容与完整结构

在一次性 MySQL 8.0.46 上用冻结 G/M9 的真实业务服务建立已付款/已关闭会话，从 M9 逐步执行 M10–M15。每步核对固定 M9 列投影摘要、精确版本链、完整列集合、索引与外键结构，以及新会话字段默认值/新增表为空。结构指纹与全部 16 个迁移文件摘要冻结在 `app/tasks/manifests/gatea_m9_m15_schema.json`；迁移文件变化会要求重新进行隔离核验。服务器只读 schema 核验与本地 M9 指纹完全相同，未在服务器执行 M15 代码或迁移。

`gatea_m15_snapshot` 在 MySQL 只读一致性事务内分批读取，每张表只输出行数和摘要；跨版本排除允许改变的新增字段，备份/恢复则比较包含 Aerich 内容在内的全部列。候选宿主可以只用标准库验证快照，不依赖安装 ORM 或 MySQL 驱动。

新增快照契约测试 26 项通过，覆盖旧内容/数量/版本/结构/默认值变化、额外业务数据、非法标识符和过期迁移 manifest。完整实际链验证在启用结构指纹拒绝后再次通过，临时 MySQL/tmpfs 均清理并复核。

备份模块现接入 M15 专用全内容快照，继续保留 M7/M8/M9 原格式。关联检查最初 86 项通过，1 项失败是测试期待内层错误而入口正确返回脱敏外层错误；修正断言后只重跑受影响的创建/恢复 5 项，全部通过。M15 恢复内容不同仍清理临时实例且不发布成功记录。此能力仍依赖尚待完成的 M15 deployment/replay、stage、CI 完整演练和验收/finalize 入口，不可单独部署。
